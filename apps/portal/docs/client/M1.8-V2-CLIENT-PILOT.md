# M1.8 V2 — Pilote visuel Client `/client`

## Version et périmètre

- Base inspectée : `fda88ead13d82109f13ee6edfc2fee9beb845c19`.
- Référence : package `fe-m1.8-product-ux-handoff-v2`, VREF-01 et VREF-02.
- Écran intégré : `/client` authentifié seulement.
- États intégrés : chargement, profil M1 disponible sans contenu programme,
  erreur récupérable et erreur réseau de déconnexion.
- Hors pilote et visuellement inchangés : `/client/today`, Coach, Auth, landing,
  API, session, RLS, SQL, données, Legacy, service worker et offline.

Le pilote utilise une variante de shell propre à l’accueil Client. Son composant
et sa feuille CSS module sont scoppés par `data-client-v2-pilot`; aucun token V2
n’est ajouté à `globals.css`.

## Composition codée

1. Sidebar 208 px à 1672 px, logo FE canonique, Accueil/Aujourd’hui et zone
   Compte/Déconnexion.
2. En-tête sombre de 88 px avec The Legacy Protocol et l’identité Client.
3. Panorama de 224 px sur desktop, 200 px sur mobile.
4. Hero factuel : « Ton portail. », « Bienvenue, {displayName}. » et
   « Accès actif ».
5. Panneau dominant : « Ton accès est confirmé. » puis « Aucune action de
   programme n’est disponible dans ce portail pour le moment. Tu n’as rien à
   compléter ici. » Aucun CTA Today n’est rendu dans ce panneau.
6. Repères secondaires issus du profil M1 : accès, absence de programme dans
   cette version et date locale calculée dans le fuseau du Client.
7. Informations de compte secondaires : nom, langue et fuseau en lecture seule.

À 390 et 320 px, le panneau factuel précède les repères et les informations
secondaires. Le menu mobile est un dialogue modal avec fermeture explicite,
piège de focus, Échap et retour du focus au bouton Menu.

## Preuves automatisées

- Géométrie 1672/390/320, hero desktop/mobile et absence de débordement.
- Palette sombre scoppée et absence de KPI/CTA programme inventé.
- Ordre mobile contexte → état factuel → informations secondaires.
- FR/EN, reflow 200 %, focus visible et menu modal au clavier.
- Chargement suspendu, timeout, erreur et Réessayer.
- Compte/Déconnexion accessibles dans les états prêt et erreur.
- E2E réel étendu : `/client/today` direct avec session persistante et zéro OTP;
  logout depuis Today; `/client` et `/client/today` refusés après logout; API
  privées 401/403 sans donnée Client.

L’E2E réel exige le harness Supabase local. Son scénario est versionné avec le
pilote; son résultat doit être joint par le gate disposant de cet environnement.
